# 部署常见问题

## 首次启动菜单为什么还要等待

首次克隆必须下载仓库并读取历史信息。v1.5.2 在同步完成后预热菜单并复用结果；网络慢、大文件多仍会影响第一次启动。持久化 `/app/cache`，查看 Git 同步日志，避免通过频繁重启或删除缓存反复触发克隆。

```bash
docker logs --tail 100 powerwiki
docker port powerwiki
```

## Git 已推送，页面为什么没有更新

1. 确认提交推送到 `config.json` 指定的仓库与分支。
2. 等待 `autoSyncInterval`，默认 180000 毫秒（3 分钟）。
3. 查看日志确认拉取成功，再重新打开文章或刷新页面。
4. 若仍不更新，检查反向代理或 CDN 是否缓存了 `/api/version` 和动态内容。

```bash
curl -fsS http://localhost:3150/api/version
```

内容版本是运行实例的标识，不是 GitHub Release 版本号。无需给缓存配置 TTL，也不需要在每次更新时删除 Git 缓存目录。

## 配置修改是否需要重启

普通站点配置会重载。仓库地址、分支、端口和环境变量修改需要重启。JSON 必须合法，可在 PowerWiki 项目目录中验证：

```bash
node -e "JSON.parse(require('fs').readFileSync('config.json', 'utf8')); console.log('JSON OK')"
```

宿主机修改只读挂载配置后，确认容器实际能看到更新；替换整个文件时，可能需要重建容器挂载。

## Git 仓库无法访问

用 `git ls-remote` 检查 URL 和目标分支，并查看服务日志中的具体错误。

```bash
git ls-remote https://github.com/steven-ld/PowerWiki-Article-Demo.git refs/heads/master
```

私有仓库需为运行环境配置 Git 凭证或 SSH 密钥，不要将令牌写入公开的配置示例。HTTPS 仓库 URL 不带 `.git` 也可能有效，不能仅靠后缀判断。

## Docker 拉取或访问失败

确认 Docker daemon 的网络与代理配置；`docker pull` 没有 `--proxy` 参数。容器需映射端口，宿主机可用 `curl` 测试；官方项目 Dockerfile 的 Alpine 基础环境可使用 `wget`，不保证有 `curl`。

```bash
docker port powerwiki
curl -fsS http://localhost:3150/api/version
docker exec powerwiki wget -qO- http://localhost:3150/api/version
```

## 统计为什么没有立刻写入文件

v1.5.2 默认每 5 秒批量写入。正常退出会保存，强制终止或断电可能丢失最近约 5 秒。历史 JSON 损坏时会尝试备份为 `.invalid-<时间戳>.bak`，再继续累计；若无法备份，应检查目录写权限和日志。

不要让多个应用实例同时写入同一统计目录。

## PDF 打开慢或内存较高

PDF 文件下载仍受体积和网络影响；页面按可见区域渲染。对比初次打开、滚动和离开页面后的资源变化，先检查文件大小与浏览器控制台，不要删除服务端 Git 缓存来处理浏览器渲染问题。

## 如何验证缓存优化

用开发者工具观察重复打开同一文章时是否复用正文，以及版本检查、访问计数的轻量请求。正常缓存测试应关闭 Network 面板中的「Disable cache」。参见 [性能与缓存](/post/02-核心功能/性能与缓存.md)。

## 图片或链接打不开

确认文件已提交，路径大小写与仓库一致。本站文章入口使用 `/post/路径.md`，图片使用 Markdown 相对路径或仓库根路径；目录页需明确指向 `README.md`，不能把文件夹地址当作文章。
