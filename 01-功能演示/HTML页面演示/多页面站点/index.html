MULTI-PAGE SITE · SANDBOXED

一个真正的多文件站点，也能安全运行

这不是一张孤立的 HTML 长页，而是由多个页面、共享样式脚本和 static/ 数据模块组成的小站点。每个页面都在头部声明 <meta name="powerwiki-render" content="sandbox">， 由 PowerWiki 放进没有同源权限的 iframe 中渲染。

这个演示实际用到了什么

每一项都对应一个刚刚补齐的路由能力，点开任意页面都能验证。

/

目录索引

链接写 guide/，/full/ 自动返回 guide/index.html，不必在地址里写死文件名。

↗

相对跳转

页面之间只用相对路径互相链接，在文章 iframe 和独立打开的 /full/ 标签页里都成立。

#

共享资源

所有页面引用同一份 assets/site.css 与 assets/site.js，样式和交互只维护一处。

{}

数据模块

页面脚本读取 static/data.js，渲染下方的页面清单与模块列表。

目录结构

链接目标、共享资源、数据文件和页面本身，全部放在同一个目录树里。

下面这份清单来自 static/data.js，由共享脚本渲染。

    为什么不是 static/data.json？

    /full/ 只放行 HTML 与精选静态资源（图片、CSS/JS、字体、音视频、WASM）。 JSON、YAML、TXT 这类数据文件不在允许列表里，避免把仓库里的配置或私密内容变成可直接下载的文件。 需要共享数据时，像本页一样使用 JS 数据模块。

    安全默认值： /full/ 会拒绝路径穿越、隐藏路径段、指到仓库外的符号链接，以及超过 50 MB 的文件； 数据类文件只在显式的 static/ 目录里提供。
