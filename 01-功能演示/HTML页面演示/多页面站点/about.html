ABOUT · SANDBOX BOUNDARIES

关于这个站点

它是一个普通的多文件网站：页面、CSS、JavaScript 和数据文件各司其职。 特殊之处在于它跑在 PowerWiki 的沙箱里 —— 页面可以交互，但拿不到 Wiki 的身份和数据。

回到首页 → 阅读指南

三条边界

沙箱不是禁用 JavaScript，而是去掉“和 Wiki 同源”这件事。

◎

同源权限

iframe 不包含 allow-same-origin，页面运行在不透明源里， 读不到 Wiki 的 Cookie、localStorage、IndexedDB，也不能调用同源 API。

~

存储

本演示的主题切换用 try / catch 包住 Web Storage： 在沙箱里写入会被拒绝，页面继续工作，只是跳转后不再记住选择。

↗

导航

页面内部的相对跳转始终可用；要跳出沙箱或打开新窗口， 需要 allow-popups 等显式能力，并且顶层跳转要由用户点击触发。

文章 iframe 的 sandbox 属性

允许脚本、表单、弹窗、下载和用户触发的顶层导航，但不允许同源。

sandbox="allow-scripts allow-forms allow-popups allow-modals
         allow-downloads allow-top-navigation-by-user-activation"
独立打开时： /full/<仓库路径> 用响应头 Content-Security-Policy: sandbox … 施加同样的限制， 并附带 nosniff、no-store 和同站资源策略。

主题同步

沙箱读不到 Wiki 的 localStorage 和 data-theme， 所以父页面会通过 postMessage 把界面偏好传进来；站点切换主题时会再次广播。 

// 父页面 → 沙箱 iframe
{ type: 'powerwiki:context', version: 1, theme: 'dark', lang: 'zh-CN' }

// 沙箱也可以先索取一次，减少首屏闪烁
parent.postMessage({ type: 'powerwiki:request-context' }, '*');
只传界面偏好： 消息里没有 Cookie、统计数据或仓库内容。页面的本地主题按钮仍然可用， 下一次站点主题变化时再与站点对齐。

技术组成

没有构建步骤，全部是仓库里的静态文件。

页面

index.html、guide/index.html、modules.html、about.html

共享资源

assets/site.css 负责样式与深浅色变量，assets/site.js 负责主题、导航高亮与数据渲染。

数据

static/data.js 提供站点页面与模块清单，首页和模块页都从这里读取。
