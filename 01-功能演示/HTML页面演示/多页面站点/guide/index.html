GUIDE · DIRECTORY INDEX

搭建这个站点的四步

当前页面是 guide/index.html，而地址栏里访问的是 guide/。 目录索引让多页面站点可以像普通网站一样组织链接，而不需要把每个文件名都写进导航。

看看模块清单 → 返回首页

四步

每一步都对应仓库里的一个真实文件，可以直接对照源码。

  1. 在页面头部声明沙箱模式

    只有带这个 meta 的 HTML 才会以完整页面运行；没有它，文章仍然走安全清洗路径。

    <meta name="powerwiki-render" content="sandbox">

  2. 用目录索引组织页面

    把页面放进目录并命名为 index.html，链接就可以只写目录名。无扩展名的链接会补 .html。

    guide/     →  guide/index.html
modules    →  modules.html
about.html →  about.html

  3. 共享 CSS 与 JavaScript

    每个页面用相对路径引用同一份资源，子目录页面用 ../ 回到站点根目录。

    <link rel="stylesheet" href="../assets/site.css">
<script src="../assets/site.js"></script>

  4. 把数据放进 static/ 模块

    页面脚本读取数据后渲染列表。数据文件放在 static/ 下，和页面资源一起随站点分发。

    <script src="../static/data.js"></script>
<script>
  renderModules(window.SITE_DATA.modules);
</script>

同一份文件，两种入口

页面内容完全相同，区别只在于由谁来承载它。

文章视图

通过 /post/…/多页面站点/index.html 打开时，PowerWiki 渲染文章外壳， 正文位置是一个 <iframe sandbox>，页面在不透明源里运行。

独立页面

通过 /full/…/多页面站点/ 打开时，浏览器直接加载原始 HTML， 响应头带 Content-Security-Policy: sandbox …，适合排查问题和单独分享。

注意：两种入口都不授予同源权限。页面读不到 Wiki 的 Cookie、localStorage 或 IndexedDB， 也不能调用同源 API；主题切换只在当前文档内生效，跳转后会回到系统默认值。
